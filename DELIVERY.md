# Delivery — Lumen 14.8 · pass 10 (the `COLLAB.md` §15.10 list)

Everything is built from this repository, headless, on Linux x86-64: no Android Studio, no GUI. The website in `../` serves all three
artefacts; the WebAssembly build is linked into the page at `/app` (and `/webapp`).

## How it was built

```bash
# once, headless (rustup + wasm32 + Windows + Android targets, JDK 17, Android SDK 34 / NDK r26, mingw-w64)
./setup-android-env.sh
rustup target add wasm32-unknown-unknown x86_64-pc-windows-gnu aarch64-linux-android
cargo install wasm-bindgen-cli --version 0.2.130     # or the prebuilt release binary

./build-all.sh          # web → android → windows, into ../public
# or individually
./build-web.sh && ./build-android.sh && ./build-windows.sh
```

The three builds are reproducible from a clean tree (the Android script prints the exact NDK/minSdk values it used; the web build stamps
`version.json`). `../public/downloads/SHA256SUMS.txt` is regenerated by `./make-sums.sh`, which every build script calls.

## The website (`../`, Next.js + PostgreSQL)

| Route | What it does |
|---|---|
| `/` | landing page: what the app is, the six feature groups, a one-click **Run Lumen here** panel that embeds the WebAssembly build in an iframe, and the three downloads with their sizes and live download counts |
| `/app`, `/webapp` | the Rust app compiled to WebAssembly (rewrite in `next.config.ts`; `<base href>` so the worker/font/icon paths resolve) |
| `/downloads/*` | the static artefacts + `SHA256SUMS.txt` |
| `/api/download/[file]` | counts a download in PostgreSQL (`download_counts`, Drizzle) and **streams** the file (no redirect: behind the preview proxy a redirect built from the request URL points at an unreachable internal host). Range requests are supported, `HEAD` works, unknown names are 404 |
| `/api/collab` | the collaboration relay: opaque frames, in-memory rooms, per-device key, 30-minute idle TTL, long poll ≤ 25 s |
| `/api/collab/push` | FCM registration + "wake the other devices" (needs `FCM_SERVICE_ACCOUNT`; otherwise `501 {configured:false}`) |
| `/api/health` | Postgres health check |

Schema: `npx drizzle-kit push` (one table, `download_counts`). The relay and push routes need no database.

## What this pass added (details in `COLLAB.md` §16)

1. `collab/textcrdt.rs` — a real text CRDT (RGA) with the editor adapter, caret anchors and `merge3`; concurrent edits of one block now
   merge through it.
2. Persistent big-table tombstones (`graves.log`), per-table index checkpoint (`bidx.lst`), cell-level row merge, delta `BigGet`,
   memory-mapped reads for data files ≥ 256 MB, background compaction after a big sync.
3. IPv6: dual-stack listener, IPv6 LAN beacons, global IPv6 addresses in the hints; `dht:CODE` joins through the public BitTorrent DHT —
   no site, no lookup server.
4. Signed fail-over plans (Ed25519 host key, pinned by joiners) and a quorum for three or more editors (provisional host, step-down).
5. Revocable, expiring per-document links with their own role, enforced on the host and carried (signed) in the fail-over plan.
6. BLE pairing transport (`BlePair.java` against `pair.rs`), FCM kit, Bluetooth permissions, and `tools/phone-rig.sh` (two phones, adb +
   UI Automator).

`PROTO` = 8. A 14.7 peer is refused with the usual "incompatible version" message.

## Limits of this delivery (honest)

* No phone and no Bluetooth radio exist in the build sandbox: the APK contains `BlePair` / `FcmKit` / `CollabService` (checked in
  `classes.dex`) but the radio paths and the pairing screen are **unverified on hardware**. `tools/phone-rig.sh` is the test that closes
  that gap (`--dry-run` is what CI can do here).
* The public BitTorrent DHT could not be reached from the sandbox; the DHT client is tested against a fake node that implements
  `get_peers` / `announce_peer`.
* The delivered binaries were produced from this tree at the end of the pass; two small things landed afterwards and are **source only**
  (rebuild with `./build-all.sh` to include them): the grant-expiry connection filter simplification in `collab/mod.rs`, and the
  mmap-after-compaction fix in `lumen-store` (a stale memory map could return old bytes for a table ≥ 256 MB after a compaction; it has a
  regression test).
* The grants **UI card** and the live per-keystroke `TextOp` frames are not in this pass — the model and the API are (§16.8 items 1–2).
